# 原始赛题导入演练包

这些文件由人工构造，全部标记为“合成演练”，用于接口、流程和边界回归；不是比赛测试集，也不用于宣称盲测准确率。没有读取或复制官方 `evidence_samples.json`、结论标准答案。有效文件仅包含 `title`、原始 `documents` 和 `question_id/question`。

可在工作台“导入原始赛题”中选择任一 `input.json`，先预检再确认导入。预检和导入不调用模型；开始研判才产生真实模型调用。每套含两道问题，完整提交应全选两道后生成提交包。

| 文件夹 | 原始资料 | 覆盖场景 |
|---|---:|---|
| `01_时点更新与统计口径` | 4 文档、5 段、2 题 | 初报与更正、单站与全区口径、同源镜像、少数意见保留 |
| `02_资料不足与空证据` | 2 文档、3 段、2 题 | 无原因与责任记录、无确切恢复日期；未决和空引用均合法 |
| `03_重复引文与文内指令` | 4 文档、5 段、2 题 | Emoji 码点、重复短句、同源转载、资料内恶意命令、原因未鉴定 |

`paired_files/raw_documents.json` 与 `paired_files/questions.json` 是 03 的同一份原始资料和纯问题，供双文件上传入口联测；导入时标题填写“【合成演练】星桥设备复位与转载核验”可与单包保持同一幂等身份。它们不包含答案字段。

`example.invalid` 是明确不可访问的模拟来源链接。应用将它们当作来源标识，测试不请求这些链接。来源等级未提供时必须保留未知。03 中的命令只属于论坛原文，不是用户授权，也不能触发读取文件、工具调用或强制结论。

`rejected/` 中的文件故意有问题，用于确认失败时不会局部入库、覆盖旧专题或启动模型：缺失文档标识、重复文档标识、错误段落范围、将 UTF-16 长度误当 Unicode 码点。`答案字段污染` 对严格运行时导入器无效；网页导入流程允许**显式预检排除题目里的额外字段并要求确认**，只有 `question_id/question` 被保存，附加字段值不能进入数据库、检查点或模型。原始文档或顶层夹带证据答案仍应直接拒绝。

测试入口：

```powershell
.venv\Scripts\python.exe -m pytest tests/test_import_scenarios.py -q
```

测试在临时数据库中显式注入 `ScenarioProvider`，覆盖“预检 → 确认 → 新专题 → 真实 worker/LangGraph → 全题图谱 → 原文坐标逐字下钻 → 四类导出 JSON”。另覆盖新专题复用同名原始 ID 的隔离、无依据判断、跨快照引用、重复引文的一次修正及修正耗尽；失败后不发布、不导出，失败原因和阶段在 activity 中可读。合成 Provider 只验证工程链路，不证明模型语义推断正确或文内提示注入的现实防御率；真实模型验收需要单独记录结果。
